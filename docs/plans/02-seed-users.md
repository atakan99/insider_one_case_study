# 02 — Seed Users Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker compose up` creates the schema and loads 5,000 realistic users with their shopping events. The data is the same on each run with the same random seed.

**Architecture:** This slice adds two packages and one binary:

```
cmd/seed            applies migrations, then calls seed.Load
internal/store      embedded goose migrations, Migrate()
internal/store/storetest   test helper: one new database per test
internal/seed       Generate() (pure, no database) and Load() (pgx CopyFrom)
```

`seed` runs as a one-shot compose service. `api` starts after it completes (D-015).

**Tech Stack:** Go 1.27, `github.com/brianvoe/gofakeit/v7` v7.18.1, `github.com/pressly/goose/v3` v3.29.0, `github.com/jackc/pgx/v5` (already in `go.mod`), Postgres 17.

**Spec:** `docs/specs/02-seed-users/goal.md` and `requirements.md`.

## Global Constraints

- The language follows the country in this slice: `TR` users are `tr`, `US` users are `en` (D-013).
- All amounts are TRY. Keep money as `int64` kuruş in Go. Write it as `pgtype.Numeric{Int: big.NewInt(kurus), Exp: -2, Valid: true}`.
- Use `pgx` directly. Do not set up `sqlc` in this slice (D-016).
- `make test` must work with Docker and no Go (D-004). The Postgres for tests runs in a container too.
- Each database test creates its own database. Packages run in parallel, so a shared database causes flaky tests.
- No test reads `ANTHROPIC_API_KEY`.
- Do not run `docker compose down -v` on the default project. It deletes the user's local data. Use a separate project name for clean-volume checks.

## Open Decisions (not needed for this slice)

- **Stale seed data:** FR-3 skips the seed when users exist. On an old volume, "last 30 days" segments can become empty. The fix is `SEED_RESET=true`. The README slice documents it.
- **Multi-language campaigns:** a later slice can add them with a new seed that mixes languages in one country (D-013).

## Review Focus

1. Same `SEED_RANDOM` and seed time → identical users and events. Pinned by Task 2 `TestGenerate_Deterministic`.
2. A template near 160 characters → the 40-character first name must exist so that slice 05 can test the limit. Pinned by Task 2 `TestGenerate_EdgeCases`.
3. Summary columns drift from `events` → the segments return wrong users. Pinned by Task 3 `TestLoad_SummariesMatchEvents`, which recomputes them in SQL.
4. Second `make up` on the same volume → no duplicate users, exit code 0. Pinned by Task 3 `TestLoad_SkipsWhenUsersExist`.
5. Explicit IDs in `CopyFrom` → the identity sequence stays at 1, and the next normal insert fails with a duplicate key. Pinned by Task 3 `TestLoad_SequenceAfterCopy`.
6. `docker compose up --wait` with a one-shot service → it must return 0 after `seed` exits with 0. Checked on Compose v5.6.1 on 2026-11-09. Pinned by Task 4 Step 4.

### Task 1: Migrations, `store.Migrate` and the test database

**Files:**

- Create: `backend/internal/store/storetest/storetest.go`

**Interfaces:**
- Produces: `store.Migrate(ctx context.Context, databaseURL string) error`.
- Produces: `storetest.NewDB(t testing.TB) (url string)`. It skips the test when `TEST_DATABASE_URL` is empty.

- [ ] **Step 1: Write the migration.** One goose SQL file with `-- +goose Up` and `-- +goose Down` sections.
  - Table `users` with the columns in `goal.md`. Use `bigint GENERATED BY DEFAULT AS IDENTITY` for `id`. This allows explicit IDs from the seed.
  - Check constraints: `language IN ('tr','en')`, `country IN ('TR','US')`, `order_count >= 0`, `total_spent >= 0`.
  - Table `events` with the columns in `goal.md`. `user_id` references `users(id) ON DELETE CASCADE`.
  - Check constraints on `events`: `type IN ('cart_add','purchase')`, and `(type = 'purchase') = (amount IS NOT NULL)`, and `amount IS NULL OR amount > 0`.
  - Indexes from NFR-2.
  - The Down section drops both tables.

- [ ] **Step 2: Write `storetest.NewDB`.**
  1. Read `TEST_DATABASE_URL`. If it is empty, call `t.Skip("TEST_DATABASE_URL not set")`.
  2. Connect, then run `CREATE DATABASE t_<16 random hex chars>`.
  3. Return the URL with the new database name.
  4. In `t.Cleanup`, run `DROP DATABASE ... WITH (FORCE)`.

- [ ] **Step 3: Write the failing tests in `migrate_test.go`.**
  - `TestMigrate_CreatesTables`: after `Migrate`, both tables exist.
  - `TestMigrate_Idempotent`: a second `Migrate` returns nil.
  - `TestMigrate_RejectsBadValues`: inserts with `language = 'de'`, `country = 'GB'` and a `cart_add` with an amount each fail.

  Run: `cd backend && TEST_DATABASE_URL=... go test ./internal/store/...`
  Expected: compile error, because `Migrate` does not exist.

- [ ] **Step 4: Write `Migrate`.** Embed the files with `//go:embed migrations/*.sql`. Open a `*sql.DB` with `sql.Open("pgx", url)` from `github.com/jackc/pgx/v5/stdlib`. Call `goose.NewProvider(goose.DialectPostgres, db, fsys)` with `fs.Sub(embedFS, "migrations")`, then `provider.Up(ctx)`. Run the tests again. Expected: PASS.

- [ ] **Step 5: Start a test Postgres in `make test`.** Change the `test` target:
  1. Create the network `cc-test` if it does not exist.
  2. Run `postgres:17-alpine` with the name `cc-test-pg` on that network. Publish `127.0.0.1:55432:5432`.
  3. Wait until `pg_isready` passes in the container.
  4. Run the Go tests with `TEST_DATABASE_URL` set:
     - local Go: `postgres://test:test@127.0.0.1:55432/test?sslmode=disable`
     - Go in a container: add `--network cc-test` to `DOCKER_GO` and use host `cc-test-pg:5432`
  5. Remove the container after the tests, also when they fail. Keep the exit code of the tests.

  Run: `make test`. Expected: the store tests run and pass. They do not show as skipped.

### Task 2: The pure generator

**Files:**
- Create: `backend/internal/seed/generate.go`, `backend/internal/seed/names.go`, `backend/internal/seed/generate_test.go`
- Modify: `backend/go.mod`, `backend/go.sum`

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces:

```go
type Options struct {
    Random uint64    // SEED_RANDOM, default 42
    Now    time.Time // seed time; all times are offsets from it
    Users  int       // number of random users, default 5000
}

type User struct {
    ID                                         int64
    FirstName, LastName, Email, Phone          string
    Language, Country, City                    string
    BirthDate, CreatedAt                       time.Time
    EmailConsent, SMSConsent                   bool
    LastCartAddAt, LastPurchaseAt              *time.Time
    OrderCount                                 int
    TotalSpentKurus                            int64
}

type Event struct {
    ID, UserID  int64
    Type        string // "cart_add" or "purchase"
    AmountKurus *int64 // nil for cart_add
    OccurredAt  time.Time
}

func Generate(o Options) (users []User, events []Event)
```

- [ ] **Step 1: Write the name and city lists in `names.go`.** Write at least 60 Turkish first names and 60 Turkish last names. Include `ç`, `ğ`, `ı`, `İ`, `ö`, `ş`, `ü`. Write the city lists from `goal.md`.

- [ ] **Step 2: Write the failing tests.**
  - `TestGenerate_Deterministic`: two calls with the same options give equal slices (`reflect.DeepEqual`). A different `Random` gives different users.
  - `TestGenerate_Fields`: checks FR-6 to FR-9 and FR-12 on all users and events.
  - `TestGenerate_Ratios`: checks FR-10 with 5,000 users.
  - `TestGenerate_Summaries`: for each user, the summary fields are equal to the values from that user's events.
  - `TestGenerate_EventTimes`: each event is between `max(CreatedAt, Now-180d)` and `Now`.
  - `TestGenerate_EdgeCases`: the edge-case users from `goal.md` exist. One first name has exactly 40 characters, counted with `utf8.RuneCountInString`.
  - `TestGenerate_ExampleBrief`: at least 1 user matches the example rule in Go. The rule is: `tr`, Istanbul, a cart add in the last 30 days and no purchase in the last 30 days.

  Run: `cd backend && go test ./internal/seed/...`
  Expected: compile error, because `Generate` does not exist.

- [ ] **Step 3: Write `Generate`.** Rules:
  - Use one `gofakeit.New(o.Random)` for all random choices. Do not call `time.Now()` and do not use `math/rand` global functions.
  - IDs start at 1. Random users come first, then the edge-case users.
  - `en` names come from gofakeit. `tr` names come from the lists in `names.go`.
  - Email: `<first>.<last>.<id>@example.com`. Lowercase the names and change Turkish letters to ASCII (`ç→c`, `ğ→g`, `ı→i`, `İ→i`, `ö→o`, `ş→s`, `ü→u`). Remove other characters that are not letters.
  - Phone `TR`: `+905` plus 9 random digits. Phone `US`: `+1`, then an area code from 201 to 989, then `55501`, then 2 digits.
  - Istanbul gets 40% of `TR` users. The other cities share the rest equally.
  - 60% of users have events: 1 to 8 `cart_add` events. After each cart add, add a purchase with a 40% chance. Put it 0 to 72 hours later, but not after `Now`. Amount: 50.00 to 5,000.00 TRY.
  - Calculate the summary fields from the events of each user.

  Run the tests again. Expected: PASS.

### Task 3: `seed.Load` and `cmd/seed`

**Files:**
- Create: `backend/internal/seed/load.go`, `backend/internal/seed/load_test.go`
- Create: `backend/cmd/seed/main.go`
- Modify: `backend/internal/config/config.go`, `backend/internal/config/config_test.go`

**Interfaces:**
- Consumes: `store.Migrate`, `storetest.NewDB` (Task 1), `seed.Generate` (Task 2).
- Produces:

```go
// Load inserts the generated data. If users exist and reset is false, it
// does nothing and returns inserted == false.
func Load(ctx context.Context, pool *pgxpool.Pool, o Options, reset bool) (inserted bool, err error)

// In package config:
type SeedConfig struct {
    DatabaseURL string
    Users       int
    Random      uint64
    Reset       bool
}
func LoadSeed(getenv func(string) string) (SeedConfig, error)
```

- [ ] **Step 1: Write the failing config tests.** `LoadSeed` needs `DATABASE_URL`. Defaults: `SEED_USERS=5000`, `SEED_RANDOM=42`, `SEED_RESET=false`. A value that does not parse, or `SEED_USERS < 1`, gives an error that names the variable.

- [ ] **Step 2: Write `LoadSeed`.** Run the config tests. Expected: PASS.

- [ ] **Step 3: Write the failing tests in `load_test.go`.** Each test calls `storetest.NewDB`, then `store.Migrate`.
  - `TestLoad_InsertsAll`: the row counts equal the lengths from `Generate`. Checks FR-2.
  - `TestLoad_SkipsWhenUsersExist`: the second `Load` returns `inserted == false`, and the counts do not change. Checks FR-3.
  - `TestLoad_Reset`: with `reset == true` and a different `Random`, the rows change and the counts equal the new lengths. Checks FR-4.
  - `TestLoad_SummariesMatchEvents`: one SQL query recomputes the four summary columns from `events` and counts the users with different values. Expected count: 0. Checks FR-11.
  - `TestLoad_SequenceAfterCopy`: an `INSERT` without `id` into `users` and into `events` succeeds.
  - `TestLoad_ExampleBriefSQL`: the SQL form of the example rule with `language = 'tr'` returns at least 1 row. Checks FR-13.
  - `TestLoad_Speed`: 5,000 users load in less than 10 seconds. Checks NFR-1.

  Run: `make test`. Expected: compile error, because `Load` does not exist.

- [ ] **Step 4: Write `Load`.** Do all the work in one transaction:
  1. `SELECT EXISTS (SELECT 1 FROM users)`. If true and `reset` is false, return `false, nil`.
  2. If `reset` is true: `TRUNCATE events, users RESTART IDENTITY`.
  3. Call `Generate(o)`.
  4. `CopyFrom` into `users`, then into `events`, with explicit `id` values.
  5. Set both identity sequences to the maximum ID with `setval(pg_get_serial_sequence('users','id'), max(id))`. Do the same for `events`.
  6. Commit.

  Run the tests again. Expected: PASS.

- [ ] **Step 5: Write `cmd/seed/main.go`.**
  1. Call `config.LoadSeed(os.Getenv)`. Exit 1 on error.
  2. Call `store.Migrate`.
  3. Open a `pgxpool`, then call `seed.Load` with `Now: time.Now().UTC()`.
  4. Log one line with `slog`: either the inserted counts, or "users exist, skipping".
  5. Exit 0.
